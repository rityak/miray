# Группы прокси — общие поля

Группа выбирает, через какой узел (прокси или другую группу) пойдёт соединение. Типы: [`select`](https://wiki.metacubex.one/ru/config/proxy-groups/select/) — выбирает пользователь; [`url-test`](url-test.md) — самый быстрый по проверкам; [`fallback`](fallback.md) — первый живой по порядку; [`load-balance`](load-balance.md) — распределяет по стратегии; [`relay`](https://wiki.metacubex.one/ru/config/proxy-groups/relay/) — цепочка узлов. `select` и `relay` в miray работают как в mihomo.

```yaml
proxy-groups:
  - name: auto
    type: url-test
    proxies: [node-a, node-b]
    use: [provider1]
    url: https://www.gstatic.com/generate_204
    interval: 300
    lazy: true
    timeout: 5000
    max-failed-times: 5
    expected-status: 204
    filter: "(?i)de|nl"
    exclude-filter: "test"
    exclude-type: "Shadowsocks|Http"
    empty-fallback: COMPATIBLE
    disable-udp: false
    hidden: false
    icon: https://example.com/icon.png
```

## Переключение при отказе узла

> **miray:** в группах `url-test`, `fallback` и `load-balance` соединение не ждёт таймаута выбранного узла и не падает вместе с ним. В mihomo соединение через упавший узел получает ошибку, а группа переключится только после проверки здоровья.

Как работает (Happy Eyeballs, RFC 8305 §5):

- **Гонка.** Если выбранный узел не подключился за задержку попытки, параллельно стартует следующий кандидат группы; соединение берёт тот, кто подключился первым, второй отменяется. Задержка попытки — двойная худшая задержка последних проверок узла, от 250 мс до 2 с; у узла без проверок — 1 с.
- **Ошибка узла.** Если узел вернул ошибку раньше, следующий кандидат стартует сразу.
- Не больше двух попыток на соединение, и всё — до отправки данных: приложение отказа не видит. Касается и TCP, и новых UDP-сессий.
- **Следующий кандидат** берётся по правилам группы, но её выбор не меняется: у `fallback` — следующий живой по порядку, у `url-test` — следующий по скорости, у `load-balance` — следующий живой по порядку, без изменения хеша, привязок `sticky-sessions` и очереди `round-robin`.
- **Проигрыш гонки — не отказ.** Узел, который только медленнее обычного, не откладывается, выбор группы не меняется — группа не «скачет» от колебаний задержки. Если выбранный узел проиграл гонку `max-failed-times` раз подряд, запускается проверка здоровья группы, решает её результат.
- **Откладывание.** Узел откладывается, только когда после его ошибки подключился другой узел (если отказали оба — скорее недоступна цель, ничего не откладывается):
  - сервер не ответил (таймаут подключения, нет маршрута, нет ответа на рукопожатие QUIC) — повтор предпочтительно на узел с другим IP сервера; если тот подключился, откладываются все узлы группы с IP упавшего сервера;
  - сервер ответил (порт закрыт, ошибка TLS или протокола) — повтор можно и на другой протокол того же сервера, откладывается только этот узел.
- Отложенный узел не выбирается для новых соединений до конца проверки здоровья, которую запустил его отказ (дальше решает её результат), до смены сети или перезагрузки конфига, но не дольше 30 с.
- DIRECT, REJECT и другие встроенные выходы в группе не откладываются: их ошибка ничего не говорит об узле.

Настроек у переключения нет: оно включено всегда, когда в группе больше одного живого узла.

## name

Имя группы. Обязательно; на него ссылаются правила и другие группы.

## type

Тип группы: `select`, `url-test`, `fallback`, `load-balance`, `relay`.

## proxies

Узлы группы по именам: прокси из `proxies`, другие группы, встроенные `DIRECT`, `REJECT` и т. п.

## use

Провайдеры прокси (`proxy-providers`), узлы которых входят в группу.

## url

Адрес проверки здоровья узлов. По умолчанию — адрес проверки первого провайдера из `use`, у которого он задан, иначе `https://www.gstatic.com/generate_204`. Лучше HTTPS: некоторые провайдеры подменяют ответы на HTTP-проверки.

## interval

Как часто проверять узлы, секунды. У `url-test`, `fallback` и `load-balance` по умолчанию 300; у `select` и `relay` проверки по расписанию нет.

## lazy

Не проверять узлы, пока группой не пользуются. По умолчанию `true`.

## timeout

Тайм-аут одной проверки, миллисекунды. По умолчанию 5000. Также окно, в котором считаются отказы дозвона для `max-failed-times`.

## max-failed-times

Сколько отказов дозвона через группу подряд (в пределах `timeout`) запускают внеочередную проверку здоровья. По умолчанию 5. Отказ «connection refused» запускает проверку сразу.

> **miray:** то же число проигранных подряд гонок выбранного узла (см. «Переключение при отказе узла») запускает проверку: мёртвый сервер часто проигрывает гонку раньше, чем приходит его ошибка.

## expected-status

Какие коды ответа считать успешной проверкой: `204`, `200/204`, `200-299`. По умолчанию — любой.

## filter, exclude-filter

Регулярные выражения по именам узлов из провайдеров (и из `include-all-proxies`): брать только подходящие / убирать подходящие. Несколько выражений — через `` ` ``.

## exclude-type

Убрать узлы этих типов, через `|`: `Shadowsocks|Http`. Без учёта регистра.

## include-all, include-all-proxies, include-all-providers

Добавить в группу все прокси и все провайдеры конфига (`include-all`), только все прокси или только все провайдеры. С `filter` берутся только подходящие прокси.

## empty-fallback

Узел на случай, если в группе не осталось ни одного узла (например, `filter` ничего не нашёл). По умолчанию `COMPATIBLE` — ведёт себя как DIRECT.

## disable-udp

Не пропускать UDP через группу.

## hidden, icon

Для панелей управления: не показывать группу / значок группы. На работу ядра не влияют.

## interface-name, routing-mark

У групп больше не поддерживаются — задаются у самих прокси. Если они есть в группе, ядро пишет ошибку в лог и не применяет их.
