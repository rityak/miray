# `miray.dns`

```yaml
miray:
  dns:
    unspecified-as-block: true
```

## unspecified-as-block

Считать адрес назначения `0.0.0.0` или `::` блокировкой. По умолчанию `true`.

Так отвечают DNS-блокировщики рекламы (AdGuard DNS, NextDNS, Pi-hole, списки в `hosts`) на домены трекеров. Неуказанный адрес не бывает адресом назначения (RFC 1122 §3.2.1.3, RFC 4291 §2.5.2).

При `true`:

- соединение к такому адресу отклоняется сразу, без повторов дозвона и без открытия сокета; в логе — одна строка `unspecified destination address (0.0.0.0 or ::): blocked by DNS, not dialed`;
- если в ответе DNS есть и обычные адреса, дозвон идёт по ним, неуказанные пропускаются;
- DIRECT не открывает UDP-сессию к такому адресу; датаграмма уже открытой сессии к такой новой цели отбрасывается (строка уровня `debug`);
- то же для адреса, который приложение указало само (например, через TUN).

При `false` — как в mihomo: ядро дозванивается на `0.0.0.0`/`::`. На Windows это сразу отказ, на Linux соединение уходит на сам компьютер (к локальному сервису на том же порту). Дозвон к DIRECT повторяется до 10 раз, и каждая попытка пишет строку `warning` в лог.

Опция действует там, где сокет открывает сам miray: DIRECT и дозвон к серверам прокси. Домен, который разрешает у себя прокси-сервер, она не видит.
