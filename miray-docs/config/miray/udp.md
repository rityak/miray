# `miray.udp`

```yaml
miray:
  udp:
    timeout: 300
```

## timeout

Сколько секунд UDP-сессия живёт без трафика в обе стороны. По умолчанию 300 (5 минут).

Сессия — это сопоставление «приложение ↔ назначение» внутри ядра: через неё идут ответы, и пока она жива, у прокси-сервера остаётся тот же исходящий порт. Когда сессия закрывается, следующая датаграмма открывает новую, и собеседник видит уже другой адрес. Для DNS-запроса это неважно; для игры, звонка, P2P или WireGuard без keep-alive это обрыв.

- К портам DNS (53), NTP (123) и STUN (3478) сессия закрывается через 10 с без трафика (или через `timeout`, если он меньше), как в sing-box: это короткие запросы, и тысячи их сессий не держат память по 5 минут.
- `timeout: 0` — как в mihomo: 60 с для всех портов.

Почему 300: RFC 4787 (REQ-5) запрещает NAT закрывать UDP-сопоставление раньше 2 минут и рекомендует 5; на это рассчитаны приложения, которые шлют keep-alive (RFC 8085 §3.5). В mihomo сессия закрывалась через 60 с, sing-box и Xray держат 5 минут. Порт 3478 не входит в диапазон 0–1023, для которого RFC разрешает сокращать таймаут: так делает sing-box, а живой звонок через STUN/TURN всё равно обновляет сессию проверками ICE каждые несколько секунд (RFC 7675).

У TUN есть свой [`udp-timeout`](../inbound/tun.md#udp-timeout) — таймаут сессий в самом стеке; сессию ядра держит этот.
