# TUN

Ядро создаёт виртуальный сетевой интерфейс и забирает из него трафик системы: приложения ничего не знают о прокси, правила применяются ко всему.

```yaml
tun:
  enable: true
  stack: mips
  auto-route: true
  auto-redirect: true          # Linux
  auto-detect-interface: true
  dns-hijack:
    - any:53
  strict-route: true
  # mtu: 65535                 # miray: на Linux по умолчанию и так
  # gso: true                  # miray: на Linux у mips по умолчанию и так
  route-exclude-address:
    - 203.0.113.10/32          # адрес сервера, до которого нужен прямой путь
```

**Отличия miray коротко:** на Linux `mtu` по умолчанию 65535 (в mihomo 9000), `gso` по умолчанию включён у стека `mips`; если интерфейс с этими умолчаниями не открылся, ядро само повторяет без них. Недоступное назначение и `REJECT` приложение видит как отклонённое соединение, а не как пустой ответ. Ниже — у каждого параметра.

## enable

Включить TUN. По умолчанию `false`.

## stack

Сетевой стек, который разбирает пакеты из интерфейса и собирает из них TCP-соединения и UDP-сессии:

- `mips` (по умолчанию) — стек mihomo на основе gVisor, TCP и UDP;
- `system` — TCP отдаётся стеку ОС (NAT во внутренний TCP-листенер), UDP разбирает ядро;
- `gvisor` — TCP и UDP в gVisor;
- `mixed` — TCP как у `system`, UDP как у `gvisor`.

> **miray:** у `mips` (форк `mipstack`) буфер приёма TCP растёт по RTT и на отдаче, а выросшее окно приёма объявляется сразу, как в Linux, а не с отложенным ACK: загрузка через TUN не стоит по 25 мс на каждый буфер. У `gvisor` буфер TCP 1 МиБ с ростом до 8 МиБ (приём) и 6 МиБ (отдача) вместо 20 КиБ. `system` отбрасывает битые пакеты, а не падает.

> **miray:** у `mips` и `gvisor` приложение получает ответ на SYN только после того, как ядро соединилось с назначением (или с сервером прокси). Если дозвон не удался или сработало правило `REJECT`, приложение получает RST — для него это «соединение отклонено» (`ECONNREFUSED`, `ERR_CONNECTION_REFUSED`), и оно может сразу перейти к другому адресу или серверу. В mihomo соединение «устанавливалось» сразу и через секунды закрывалось — приложение видело пустой ответ. У `system` и `mixed` TCP-рукопожатие делает сама ОС, поэтому там отказ приходит сбросом уже установленного соединения (`ECONNRESET`). Если включён `sniffer`, ядро читает начало соединения до дозвона, и ответ на SYN уходит сразу, как раньше; отказ тогда тоже приходит сбросом.

## device

Имя интерфейса. Если не задано или не подходит для ОС, ядро выбирает свободное само: `tunN` на Linux и Windows, `utunN` на macOS.

## auto-route

Настроить маршруты так, чтобы трафик системы шёл в TUN. По умолчанию `true`.

## auto-redirect

Только Linux, нужен `auto-route`. Перенаправлять TCP через nftables вместо маршрутизации TUN: быстрее для TCP и работает для трафика, который `auto-route` не забирает (например, Docker-мосты).

## auto-detect-interface

Определять исходящий интерфейс по маршруту по умолчанию и привязывать к нему свои соединения, чтобы они не попали обратно в TUN. По умолчанию `true`.

## dns-mode

Как настраивать системный DNS:

- `disabled` — не трогать;
- `native` — назначить адрес TUN системным DNS;
- `hijack` — как `native`, и ещё перехватывать DNS-запросы на порт 53 других интерфейсов (на Windows нужен `strict-route`, на Linux — `auto-redirect`).

Не задано — `hijack` на Windows и Linux при включённом `auto-route`, иначе `disabled`; на macOS — `disabled`.

## dns-hijack

Адреса, запросы на которые отвечает DNS ядра, а не уходят дальше: `any:53` — любой адрес на порту 53, `tcp://any:53` — по TCP. По умолчанию `0.0.0.0:53`.

## strict-route

Строгая маршрутизация: на Linux — правила, которые не дают трафику уйти мимо TUN, на Windows — блокировка обхода через другие интерфейсы (в том числе утечки DNS). Может мешать локальной сети и некоторым VPN.

## mtu

MTU интерфейса.

> **miray:** по умолчанию на Linux 65535 для всех стеков, как в sing-box (в mihomo — 9000); на других ОС — 9000. Если интерфейс с 65535 не открылся, ядро повторяет с 9000 и пишет об этом в лог. Явное значение не меняется. С 65535 у `system` TCP быстрее и дешевле по CPU, у `gvisor` вчетверо меньше записей в интерфейс.

## gso

Только Linux. Пачки пакетов через интерфейс за один вызов (`vnet_hdr`, GSO на отдаче, GRO на приёме).

> **miray:** по умолчанию включён у стека `mips` на Linux (в mihomo выключен у всех); у `system` и `gvisor` выключен — им не выгоден. Явное `true`/`false` действует на любом стеке. Если интерфейс с `gso` не открылся (ядро ОС не поддерживает), ядро повторяет без него и пишет об этом в лог.

## gso-max-size

Наибольший размер пачки GSO в байтах. По умолчанию 65536.

## inet6-address

IPv6-адрес интерфейса. По умолчанию `fdfe:dcba:9876::1/126`; если `ipv6: false` — не назначается. IPv4-адрес берётся из `dns.fake-ip-range` (по умолчанию `198.18.0.1/16`), с маской /30.

## udp-timeout

Сколько секунд держать UDP-сессию без трафика. По умолчанию 300.

## icmp-timeout

Сколько секунд ждать ответа на пересылаемый ICMP-запрос (ping). По умолчанию 10.

## disable-icmp-forwarding

Ping из TUN по умолчанию уходит к адресату напрямую (мимо прокси), и ответ настоящий. С `true` ядро отвечает на ping само, не пересылая его; так же оно всегда отвечает на адреса самого интерфейса.

## iproute2-table-index, iproute2-rule-index

Linux: номер таблицы маршрутов и приоритет правил, которые создаёт `auto-route`. Менять, если они заняты.

## auto-redirect-input-mark, auto-redirect-output-mark, auto-redirect-iproute2-fallback-rule-index

Linux: метки пакетов и приоритет запасного правила для `auto-redirect`. Менять, если пересекаются с другими правилами nftables.

## endpoint-independent-nat

Отвечать на UDP с любого адреса, а не только с того, куда ушёл запрос (NAT, не зависящий от адреса назначения, RFC 4787). Нужен некоторым играм и P2P; немного дороже.

## congestion-controller

Алгоритм управления перегрузкой TCP внутри стека `mips`: `cubic` (по умолчанию), `reno`, `bbr`, `bbr3`. На другие стеки не действует.

## route-address, route-exclude-address

Только с `auto-route`. Подсети, которые направлять в TUN (вместо всего трафика) и которые направлять мимо него. В `route-exclude-address` — адреса, до которых нужен прямой путь: локальные сети, серверы, к которым подключение должно идти не через ядро.

## route-address-set, route-exclude-address-set

То же, но подсети берутся из rule-provider типа `ipcidr` по имени; на Linux нужен `auto-redirect`.

## include-interface, exclude-interface

Linux: забирать в TUN трафик только этих интерфейсов / всех, кроме этих. Взаимоисключаются.

## include-uid, include-uid-range, exclude-uid, exclude-uid-range

Linux: забирать трафик только этих пользователей / всех, кроме этих. Диапазон — `1000:9999`.

## exclude-src-port, exclude-src-port-range, exclude-dst-port, exclude-dst-port-range

Не забирать трафик с этих портов источника или назначения. Диапазон — `1000:2000`.

## include-mac-address, exclude-mac-address

Linux с `auto-redirect`: забирать трафик только устройств с этими MAC (роутер, раздача) / всех, кроме этих.

## include-android-user, include-package, exclude-package

Android: забирать трафик только этих пользователей и приложений / всех, кроме этих приложений.

## loopback-address

Linux с `auto-redirect`: TCP-соединение к этим адресам соединяется обратно с адресом источника (как в SideStore/StosVPN с `10.7.0.1`).

## file-descriptor

Использовать уже открытый интерфейс по номеру дескриптора (его открывает приложение-обёртка, например на Android) вместо создания своего.

## recvmsgx, sendmsgx

macOS: пакетный приём и отправка через интерфейс. По умолчанию `recvmsgx: true`, `sendmsgx: false` (при многопоточной загрузке может подвесить систему).

## Устаревшие параметры

`inet4-route-address`, `inet6-route-address`, `inet4-route-exclude-address`, `inet6-route-exclude-address` — прежние имена `route-address` и `route-exclude-address`; работают, но лучше перейти на новые.
