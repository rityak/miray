# DNS

```yaml
dns:
  enable: true
  listen: 0.0.0.0:1053
  ipv6: false
  enhanced-mode: fake-ip
  fake-ip-range: 198.18.0.1/16
  fake-ip-filter: ["*.lan"]
  default-nameserver: [223.5.5.5]
  nameserver: [https://dns.alidns.com/dns-query]
  nameserver-policy:
    "+.arpa": 10.0.0.1
  proxy-server-nameserver: [https://doh.pub/dns-query]
  direct-nameserver: [system]
```

**Отличия miray коротко:**

- просроченная запись кеша отдаётся, пока обновляется, не дольше 3 дней после истечения — см. [кеш](#кеш);
- OPT (EDNS) — свой на каждом шаге: клиенту — только если он прислал свой, OPT сервера не передаётся — см. [`listen`](#listen);
- соединения к серверам `tcp://` и `tls://` переиспользуются, но не после 10 с простоя, а забытое сервером соединение заменяется за 2 с — см. [типы серверов](#типы-серверов);
- кеш и соединения к серверам переживают reload, если блок `dns` не менялся ([API](../../api/index.md));
- ответ `0.0.0.0`/`::` — блокировка ([`miray.dns`](../miray/dns.md)).

## enable

Включить DNS ядра. По умолчанию `false`: тогда имена разрешает система.

## listen

Адрес DNS-сервера ядра (UDP и TCP), например `0.0.0.0:1053`. На него же отвечает перехват DNS у TUN (`dns-hijack`).

> **miray:** OPT в ответе — свой, размер 1232 байта (рекомендация DNS Flag Day 2020), и только клиенту, который прислал OPT в запросе (RFC 6891 §6.1.1: OPT действует на один шаг и не пересылается). В mihomo при промахе кеша клиенту уходил OPT вышестоящего сервера, в том числе клиенту без EDNS.

## ipv6

Отвечать ли на запросы AAAA. По умолчанию `false`: на AAAA — пустой ответ, у назначений по домену только IPv4.

`ipv6-timeout` — сколько миллисекунд ждать ответа AAAA после A, по умолчанию 100. Если A не пришёл, ядро дожидается AAAA, а не возвращает ошибку.

## enhanced-mode

`redir-host` (по умолчанию) — приложение получает настоящие адреса; `fake-ip` — адрес из `fake-ip-range`, соответствие домену ядро помнит и по нему маршрутизирует.

## fake-ip-range, fake-ip-range6

Диапазоны адресов fake-ip, IPv4 (по умолчанию `198.18.0.1/16`, от него же берётся адрес TUN) и IPv6.

## fake-ip-filter, fake-ip-filter-mode

Домены, которым не выдаётся fake-ip (маски доменов, наборы `rule-set:`, `geosite:`). Режим — `blacklist` (по умолчанию: фильтр — исключения), `whitelist` (fake-ip только доменам фильтра) или `rule`: фильтр — список правил сверху вниз (`DOMAIN*`, `GEOSITE`, `RULE-SET`, `MATCH`) с действием `fake-ip` или `real-ip`.

## fake-ip-ttl

TTL ответов fake-ip. По умолчанию 1; менять без причины не нужно.

## use-hosts, use-system-hosts

Отвечать ли из `hosts` конфига и из системного файла hosts. Оба по умолчанию `true`.

## respect-rules

Соединения к DNS-серверам идут по правилам `rules`, как обычный трафик. Нужен `proxy-server-nameserver`, иначе имя сервера прокси нечем разрешить. С `prefer-h3` вместе не рекомендуется.

## default-nameserver

Серверы для разрешения имён самих DNS-серверов из `nameserver`. Только IP-адреса; можно шифрованный DNS по IP.

## nameserver, nameserver-policy

`nameserver` — основные серверы. `nameserver-policy` — серверы для отдельных доменов: ключ — маска домена, `geosite:` или `rule-set:`, значение — сервер или список; политика важнее `nameserver` и `fallback`.

## proxy-server-nameserver, proxy-server-nameserver-policy

Серверы только для имён серверов прокси. Пусто — как для остальных имён. Политика действует, только если задан `proxy-server-nameserver`.

## direct-nameserver, direct-nameserver-follow-policy

Серверы для имён, которые уходят в DIRECT. Пусто — как для остальных. `direct-nameserver-follow-policy: true` — учитывать для них и `nameserver-policy`.

## fallback, fallback-filter

`fallback` — запасные серверы; с ними включается `fallback-filter`, который решает, когда ответу `nameserver` не верить:

- `geoip` (по умолчанию `true`), `geoip-code` (по умолчанию `CN`) — адрес не из этой страны считается подменённым, берётся ответ `fallback`;
- `ipcidr` — ответы из этих сетей считаются подменёнными;
- `domain` — эти домены сразу спрашиваются у `fallback`;
- `geosite` — то же для наборов geosite; устарело, вместо него — `nameserver-policy`.

`fallback-lazy-query: true` — спрашивать `fallback`, только когда ответ `nameserver` не прошёл фильтр (по умолчанию оба сразу).

## prefer-h3

Для DoH сначала пробовать HTTP/3.

## Кеш

`cache-algorithm` — `lru` (по умолчанию) или `arc`; `cache-max-size` — сколько ответов держать, по умолчанию 4096.

Ответ живёт в кеше по своему TTL; TTL 0 не кешируется, отказ сервера (SERVFAIL) — 5 с. Запись с истёкшим TTL отдаётся сразу с TTL 1 и тут же обновляется в фоне.

> **miray:** просроченная запись отдаётся так не дольше 3 дней после истечения TTL (RFC 8767 §5: предел от 1 до 3 дней, у sing-box 3 дня); старше — сначала новый запрос, как при промахе. В mihomo предела нет: запись имени, которое не спрашивали неделями, возвращалась как есть, и первое соединение шло на старый адрес. Кеш переживает reload конфига, если блок `dns` не менялся.

## Типы серверов

Адрес сервера в `nameserver`, `fallback`, политиках и прочих списках:

| Запись | Сервер |
|---|---|
| `223.5.5.5`, `udp://223.5.5.5:53` | обычный DNS по UDP (с переходом на TCP при обрезанном ответе) |
| `tcp://223.5.5.5` | DNS по TCP |
| `tls://dns.google` | DNS over TLS, порт 853 |
| `https://dns.google/dns-query` | DNS over HTTPS |
| `quic://dns.adguard.com` | DNS over QUIC, порт 853 |
| `system` | системный резолвер |
| `dhcp://en0` | DNS, который выдал DHCP на интерфейсе |

> **miray:** соединение `tcp://` и `tls://` после ответа возвращается в пул и берётся следующим запросом (у `tcp://` — до 4 на сервер, у `tls://` — до 8). Соединение, простоявшее в пуле дольше 10 с, закрывается, а не берётся: серверы закрывают свои через 10–30 с простоя (RFC 7766 §6.2.3). Если на взятом из пула соединении ответа нет 2 с — сервер или NAT его молча забыли, — запрос уходит заново по новому соединению. В mihomo `tcp://` открывал соединение на каждый запрос, а забытое соединение `tls://` занимало весь таймаут запроса (5 с), и запрос падал.

## Параметры сервера

После адреса через `#`, несколько — через `&`:

```yaml
dns:
  nameserver:
    - "https://8.8.8.8/dns-query#proxy&ecs=1.1.1.1/24&ecs-override=true"
```

- имя прокси или группы (`#proxy`) — ходить к серверу через него; если такого нет — через интерфейс с этим именем; `#RULES` — по правилам, как `respect-rules`. Имя сервера прокси тогда разрешает `proxy-server-nameserver`;
- `h3=true` — DoH только по HTTP/3;
- `skip-cert-verify=true` — не проверять сертификат; `name-cert-verify=<имя>` — проверять сертификат на это имя, SNI не меняется;
- `disable-reuse=true` — у `tls://` не переиспользовать соединения;
- `ecs=<подсеть>` — добавлять в запрос EDNS Client Subnet; `ecs-override=true` — заменять подсеть, которую прислал клиент;
- `disable-ipv4=true`, `disable-ipv6=true`, `disable-qtype-<номер>=true` — отбрасывать ответы A, AAAA или этого типа (например `disable-qtype-65` — HTTPS).

> **miray:** `ecs` дописывается в OPT запроса, сколько бы записей ни шло за ним; новый OPT — с размером 1232. В mihomo, если за OPT в запросе стояла другая запись, добавлялся второй OPT, и сервер отвечал FORMERR.
