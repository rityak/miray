# API

Пути, методы и авторизация (`secret`) — как в [mihomo](https://wiki.metacubex.one/ru/api/). Ниже — где ответы и поведение в miray иные.

## GET /configs

> **miray:** в ответе есть объект `miray` — текущие значения [блока `miray`](../config/miray/index.md):
>
> ```json
> "miray": { "dns": { "unspecified-as-block": true } }
> ```

`PATCH /configs` блок `miray` не меняет; его меняет только reload.

## PUT /configs — reload

Перечитывает конфиг из файла (`path`) или из тела запроса (`payload`) и применяет его целиком, включая блок `miray`.

> **miray:** reload не прерывает работу ядра.
>
> - **Providers грузятся заранее.** `proxy-providers` и `rule-providers` нового конфига загружаются (из файла или скачиваются), пока старый конфиг обслуживает соединения. Ядро приостанавливается только на саму замену конфига. Provider, который не загрузился через старый конфиг (например, его прокси есть только в новом), один раз загружается заново после замены. В mihomo новые соединения отбрасываются всё время загрузки providers.
> - **Новые соединения ждут.** TCP-соединение, пришедшее во время замены, ждёт её конца (до 5 с) и идёт уже по новому конфигу. В mihomo оно закрывается сразу.
> - **UDP-сессии не рвутся.** Установленные UDP-сессии продолжают передавать датаграммы. В mihomo датаграммы живых сессий отбрасываются, пока применяется конфиг.
> - **DNS остаётся тёплым.** Если раздел `dns:` не изменился, сохраняется кеш DNS-ответов. Если к тому же те же `interface-name` и `routing-mark`, а DNS-серверы не ходят через прокси, сохраняются и открытые соединения DoT, DoH, DoQ и TCP к ним. В mihomo каждый reload начинается с пустого кеша и новых рукопожатий.
> - **QUIC-входы закрываются явно.** Вход `listeners:`, который пересоздаётся, закрывает соединения кадром CONNECTION_CLOSE — [остановка и reload](../config/inbound/listeners/index.md#остановка-и-reload).

Входы, у которых настройка не изменилась, продолжают работать; изменённые и удалённые закрываются — как в mihomo.
