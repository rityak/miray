# miray

Форк [mihomo](https://github.com/MetaCubeX/mihomo). Рабочая ветка — `dev`.

## Фичи

TUN
- `gso` включён по умолчанию для стеков mips и system: скорость на потолке +43%, CPU на гигабайт −30%.
- Если TUN с `gso` не открылся, он запускается без него.
- TUN со стеком `system` на Linux по умолчанию с MTU 65535, как в sing-box: CPU клиента на TCP −7% на канале 100 Мбит/с, на плотном потоке выигрыш больше. Если с 65535 TUN не открывается — берётся 9000; явный `mtu:` не трогается.
- gvisor: буфер TCP 1 МиБ с ростом до 8/6 МиБ вместо 20 КиБ. TCP через gvisor больше не упирается в окно.
- mipstack: буфер приёма TCP растёт и на отдаче через TUN.
- Битый пакет из TUN больше не роняет процесс (стек system).

UDP
- Клиент ss читает ответы пачками: потолок загрузки через TUN 289 → 374 Мбит/с.
- Входящий UDP читается пачками (`recvmmsg`): потолок ss UDP вырос с 297 до 435 Мбит/с, CPU клиента на гигабайт −28%.
- DIRECT отправляет пачками (`sendmmsg`) и через UDP GSO, а ответы читает пачками (`recvmmsg`): CPU сервера на загрузке −3%.
- ss UDP шифрует и отправляет пачками: CPU клиента на гигабайт −17%, на потолке −24%. Теперь клиент тратит меньше CPU, чем sing-box: на 12% через `tunnels:`, на 16% через TUN.
- ss-сервер отдаёт ответы пачкой: CPU сервера на загрузке −9%.
- Пакеты уже открытых UDP-потоков TUN идут в обход общей очереди.
- Ответы по UDP через прокси читаются без лишней горутины на каждую датаграмму: на загрузке CPU клиента −17% (ss через TUN, 50 Мбит/с).
- Клиент ss через `tunnels:` отдаёт ответы UDP пачкой, а не по одной датаграмме: на загрузке CPU клиента −8%, теперь наравне с sing-box (было на 13% дороже).
- hysteria2 и tuic больше не переставляют датаграммы одного потока.
- UDP через hysteria2 тратит меньше CPU: на канале 50 Мбит/с сервер −4%, аллокаций на датаграмму на треть меньше.
- trusttunnel больше не обрезает загрузку: раньше при закрытии соединения терялись последние ~16 КиБ.
- VLESS через XHTTP (`stream-one`, `stream-up`) больше не теряет данные при закрытии соединения: раньше пропадал хвост загрузки, а короткая загрузка могла не дойти совсем.
- tuic больше не режет датаграммы длиннее ~1170 байт на две, если путь пропускает их целиком: на таких датаграммах (например, QUIC внутри туннеля) CPU клиента −12%, сервера −7% на канале 50 Мбит/с.
- hysteria2 с обфускацией Salamander на Linux тратит на 61% меньше CPU у клиента и на 48% у сервера (100 Мбит/с): пакеты снова уходят и принимаются пачками, XOR идёт словами. Теперь Salamander почти бесплатен по сравнению с hysteria2 без обфускации. Выключается `MIRAY_SALAMANDER_OOB=off`.
- hysteria2 и tuic на Linux принимают пакеты пачками через UDP GRO: на канале 100 Мбит/с CPU принимающей стороны −3%, на плотном потоке выигрыш больше. Выключается переменной `MIRAY_QUIC_GRO=off`.
- tuic теряет вчетверо меньше UDP в начале сессии (на канале 50 Мбит/с ~1090 → ~235 датаграмм, почти как sing-box): датаграммы больше не забивают в QUIC остальные данные, аутентификация не ждёт их очередь, а TCP и UDP идут по одному соединению — новой UDP-сессии не нужно своё рукопожатие.
- Открытые UDP-сессии не теряют пакеты во время reload конфига.

Reload и DNS
- Reload без простоя: providers грузятся, пока работает старый конфиг. Новое TCP-соединение ждёт окончания reload, а не сбрасывается.
- Кеш DNS и открытые соединения к DNS-серверам переживают reload, если раздел `dns:` не менялся.
- DNS `tcp://` держит соединения открытыми, а не открывает новое на каждый запрос.
- Медленный DNS не блокирует остальной трафик и reload.

TCP
- Нет лишних 200 мс ожидания early-data для серверов, которые говорят первыми (SSH, SMTP).
- При переборе адресов каждый получает свою долю таймаута.

QUIC (hysteria2, tuic)
- Нет лагов под загрузкой: BBR больше не забивает очередь канала раз в 10 секунд. Игровой пакет через hysteria2 рядом с загрузкой 80 Мбит/с: p99 63 → 44,5 мс, выбросы +40 мс пропали.
- UDP через hysteria2 и tuic отправляется GSO-пачками: CPU клиента −14%, сервера на загрузке −9%.
- Очередь входящих пакетов 4096 вместо 256: потолок hysteria2 ×1,5, CPU клиента на гигабайт −30%.
- Соединение переживает переполненный буфер сокета и смену сети.
- GREASE QUIC bit: на один признак QUIC для DPI меньше.
- На Windows отправка пачками через USO.

Остальное
- utls и reality: все TLS-записи одного `Write` уходят одним системным вызовом.
- smux: запись, брошенная по таймауту, больше не уходит в сеть с чужими данными.
- Исправлены гонки данных в XTLS Vision, restls и anytls.
- Апдейтер не ставит mihomo поверх miray.
