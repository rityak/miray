# miray

Форк [mihomo](https://github.com/MetaCubeX/mihomo). Рабочая ветка — `dev`.

## Что изменено в ядре

Замеры и обоснования — во внутренней документации проекта, здесь только сами изменения.

### TUN
- `gso` включён по умолчанию для стека `mips` на Linux (у `system` при MTU 65535 выключен, `gso: true` включает); если TUN с ним не открылся — запуск без него.
- MTU TUN на Linux по умолчанию 65535, как в sing-box, для всех стеков, с откатом на 9000; явный `mtu:` не трогается.
- gvisor: буфер TCP 1 МиБ с ростом до 8/6 МиБ вместо 20 КиБ.
- mipstack: буфер приёма TCP растёт и на отдаче.
- mips: окно приёма TCP, выросшее после чтения приложения хотя бы вдвое, объявляется сразу, как в Linux, а не с отложенным ACK: загрузка через TUN больше не стоит по 25 мс на каждый буфер приёма (форк `mipstack`).
- Стек `system` отбрасывает битые пакеты, а не падает.

### UDP: общий путь
- Пакеты уже открытых UDP-потоков TUN идут в сессию напрямую, мимо общей очереди и NAT-таблицы.
- Входящий UDP листенеров и ответы исходящих сессий читаются пачками (`recvmmsg`); у листенеров — своим `recvmmsg` без разбора и аллокации адреса на каждую датаграмму.
- Пакетное соединение листенера (ss, hysteria2, tuic и др.) собирает метаданные раз на соединение, датаграмма берёт только своё назначение; обратный писатель сессии не перезаписывается на каждой датаграмме.
- DIRECT отправляет пачками (`sendmmsg`) и через UDP GSO.
- Ответы сессии, уже прочитанные пачкой, уходят клиенту тоже пачкой — и в TUN, и в `tunnels:`.
- Чтение ответов без горутины, `select` и лишних аллокаций на каждую датаграмму; адрес источника кешируется на сессию.
- Открытые UDP-сессии переживают reload конфига без потерь.
- Очередь UDP-сессии (пока прокси дозванивается или исходящий медленнее источника) ограничена временем, а не числом: датаграмма, прождавшая дольше 250 мс, выбрасывается при выходе из очереди, а не отправляется с опозданием; по числу — только потолок памяти, 1024.

### Shadowsocks
- Клиент ходит на сервер через подключённый UDP-сокет и читает ответы пачками своим `recvmmsg`.
- Клиент и сервер шифруют и отправляют UDP пачками (`sendmmsg` / UDP GSO).
- Полный TCP-чанк (64 КиБ данных и тег AEAD, так шлёт сервер sing-box) читается в буфер из пула, а не в новый буфер из кучи на каждый чанк: в пуле `common/pool` и `sing` есть класс 72 КиБ, `buf.NewSize` берёт из пула и выше 64 КиБ.

### QUIC: hysteria2 и tuic
- BBR не переполняет очередь канала периодическими пробами: нет всплесков задержки под загрузкой.
- Отправка GSO-пачками, приём через UDP GRO (`MIRAY_QUIC_GRO=off` выключает), на Windows — USO.
- Очередь входящих пакетов 4096 вместо 256.
- Соединение переживает переполненный буфер сокета и смену сети; GREASE QUIC bit.
- Датаграммы одного потока не переставляются.
- hysteria2: дешевле путь UDP; Salamander снова шлёт и принимает пачками, XOR по словам (`MIRAY_SALAMANDER_OOB=off` выключает).
- hysteria2-сервер отвечает на TCP-запрос сразу после соединения с целью, как sing-box: официальный клиент hysteria ждёт этого ответа, прежде чем слать данные.
- hysteria2-клиент, закрывая TCP-поток до ответа сервера, закрывает только отправку, как официальный клиент: сервер успевает ответить и доставить загрузку.
- hysteria2-сервер доставляет загрузку клиента, который перестал читать до ответа (STOP_SENDING, клиент sing-box на закрытии): ошибка записи ответа не обрывает соединение, как у официального сервера.
- tuic: датаграммы не забивают остальные данные QUIC, аутентификация не ждёт их очередь, TCP и UDP идут по одному соединению; большие датаграммы не режутся на две, если путь их пропускает.
- После рестарта сервера QUIC-клиенты (hysteria2, tuic, trusttunnel по QUIC, masque) переподключаются сразу, а не через idle-таймаут: на Linux сокет клиента получает ICMP «порт закрыт» (`IP_RECVERR`).
- Серверы hysteria2 и tuic на остановке и reload закрывают соединения с CONNECTION_CLOSE, как sing-box: клиенты (в том числе официальный hysteria) переподключаются сразу, а не через idle-таймаут. На остановке закрываются все входы из `listeners:`, а не только TUN.

### Потоки и TLS
- Копирование потока после первых 512 КБ читает буферами в кадр писателя (его MTU или 64 КиБ, до 72 КиБ с заголовками), как sing-box: писатель чанков (ss2022, AEAD) получает полные чанки вместо двух по 32 КиБ.
- VLESS XHTTP (все режимы, в том числе `packet-up` с сервером Xray) и trusttunnel не теряют хвост данных при закрытии соединения.
- XTLS Vision не теряет последние байты, пришедшие вместе с закрытием TLS.
- Сервер VMess не теряет данные клиента, первый чанк которого длиннее 4 КиБ (клиенты sing-box и Xray): остаток чанка после подглядывания ранних данных больше не пропадает (форк `sing`, `bufio.ChunkReader`).
- utls и REALITY: все TLS-записи одного `Write` уходят одним системным вызовом.
- smux: запись, брошенная по таймауту, не уходит в сеть с чужими данными.
- Исправлены гонки данных в XTLS Vision, restls, anytls, trusttunnel (чтение ответа при закрытии клиента), сервисе hysteria2 (`Start`/`Close`) и UDP NAT sing (адрес сессии при NAT rebinding).
- `tls.custom-certifactes` действуют и для прокси, которые собирают TLS при создании (hysteria2, tuic, HTTPS- и TLS-SOCKS5-прокси): сертификаты загружаются до разбора прокси. Раньше такой сервер проходил только с `skip-cert-verify` или отпечатком.

### TCP, DNS, reload
- Reload без простоя: providers грузятся, пока работает старый конфиг; новое соединение ждёт конца reload, а не сбрасывается.
- Кеш DNS и соединения к DNS-серверам переживают reload, если `dns:` не менялся; DNS `tcp://` держит соединения открытыми; медленный DNS не блокирует остальной трафик.
- Нет 200 мс ожидания early-data для серверов, которые говорят первыми (SSH, SMTP); при переборе адресов каждый получает свою долю таймаута.

### OpenVPN
- Без `auth` в конфиге клиент берёт SHA1, как сам OpenVPN: tls-auth и шифры без AEAD работают с сервером, у которого `auth` тоже не задан. Явный `auth` работает как раньше.

### Группы прокси
- `url-test`, `fallback`, `load-balance`: соединение (TCP или UDP-сессия) не ждёт таймаута узла. Если узел не подключился за задержку попытки (двойная худшая задержка его последних проверок, 250 мс … 2 с; без истории — 1 с), параллельно стартует следующий кандидат группы, соединение берёт тот, кто подключился первым, второй отменяется (Happy Eyeballs, RFC 8305 §5); если узел вернул ошибку раньше — следующий стартует сразу. Не больше двух попыток, всё до отправки данных — приложение отказа не видит.
- Проигрыш гонки — не отказ: медленный (лагающий) узел не откладывается и выбор группы не меняется. Отказ — только ошибка узла, после которой другой узел подключился; если отказали оба — вероятнее недоступна цель, узлы не откладываются. Если узел группы проиграл гонку `max-failed-times` раз подряд (по умолчанию 5), запускается проверка здоровья, решает её вердикт.
- Стадия отказа: сервер не ответил (таймаут подключения, нет маршрута, нет ответа на рукопожатие QUIC) — повтор предпочтительно на узел с другим IP сервера, и если тот подключился, откладываются все узлы группы с IP упавшего сервера; сервер ответил (отказ порта, ошибка TLS или протокола) — повтор можно и на другой протокол того же сервера, откладывается только узел.
- Отложенный узел не выбирается для новых соединений до конца проверки здоровья, которую запустил его отказ (дальше решает её вердикт), до смены сети или перезагрузки конфига, но не дольше 30 с. Выбор группы при этом свой: `fallback` — по порядку, `url-test` — самый быстрый с `tolerance`, `load-balance` — по своей стратегии (хеш, sticky, round-robin); альтернатива для повтора состояние группы не меняет.

### Прочее
- Апдейтер не ставит mihomo поверх miray.
- Диагностическая сборка (тег `miraydiag`, `TAGS=miraydiag tools/scripts/build.sh`, версия `…-diag`): журнал в `miray-diag/` рядом с конфигом — JSON Lines только того, что видно пользователю или расходится со стандартами (отказ дозвона со стадией, соединение без ответа, зависание, обрыв, потерянное полузакрытие TCP, UDP без ответа и выброшенные датаграммы, возврат UDP-потока после закрытия по простою, закрытие QUIC с потерями и RTT, сбой DNS, брошенное до дозвона соединение, переключения и проверки групп, смена сети, рост горутин) и минутная сводка по узлу. Включён по умолчанию, `MIRAY_DIAG=off` выключает, `MIRAY_DIAG=dir=<папка>` — другая папка. Адреса серверов и секреты не пишутся, назначения — регистрируемый домен и хеш IP. Без тега кода журнала в бинаре нет.
